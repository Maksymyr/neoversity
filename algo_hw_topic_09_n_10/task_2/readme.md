# Завдання 2 — обчислення інтеграла методом Монте-Карло

Обчислення визначеного інтеграла `∫ f(x) dx` від `a` до `b` методом Монте-Карло й порівняння з аналітичним розв'язком та `scipy.integrate.quad`.

Обрано приклад із умови: **`f(x) = x²` на `[0, 2]`**, точне значення = `8/3 ≈ 2.6666666667`.

## Запуск

```bash
python monte_carlo_integral.py                         # 1M зразків, інтерактивні вікна
python monte_carlo_integral.py -n 100000               # 100k зразків
python monte_carlo_integral.py -a 0 -b 3.14 -n 1000000 # інший інтервал
python monte_carlo_integral.py --save                  # зберегти графіки у файли
python test_monte_carlo_integral.py                    # тести
```

## Два варіанти Монте-Карло

### 1. `monte_carlo_mean` — метод середнього значення
Семплимо `N` точок `xᵢ ~ Uniform(a, b)`, обчислюємо

```
I ≈ (b − a) · (1/N) · Σ f(xᵢ)
```

Базується на тому, що інтеграл = середнє значення функції × ширина інтервалу. Це **класична** форма MC-інтегрування — використовує всі семпли максимально ефективно. Працює і для від'ємних `f(x)`.

### 2. `monte_carlo_hit_miss` — метод «влучань»
Будуємо прямокутник `[a, b] × [0, y_max]` (де `y_max ≥ max f(x)` на інтервалі). Семплимо `N` точок `(xᵢ, yᵢ)` рівномірно в прямокутнику, рахуємо «влучання» — ті, для яких `yᵢ ≤ f(xᵢ)`. Тоді

```
I ≈ (b − a) · y_max · (hits / N)
```

Геометрично — оцінюємо площу під кривою через долю прямокутника, що під неї потрапила. Простіший для розуміння, але **менш ефективний**: інформація використовується лише бінарно (під/над), тому потрібно більше зразків для тієї самої точності. Працює лише для `f(x) ≥ 0`.

## Збіжність

При зростанні `N` похибка зменшується як `O(1/√N)` — це фундаментальна властивість Монте-Карло, що випливає з центральної граничної теореми. Емпірично: при ×100 збільшенні `N` похибка падає у ~10 разів.

## Висновки

1. **Метод Монте-Карло коректно обчислює інтеграл.** При `N = 10⁶` обидва варіанти дають результат з відносною похибкою ~0.001% — це **5 правильних значущих цифр**. Точне значення `8/3 = 2.66666...`, отримане `2.66669...` — розбіжність у 5-му знаку.

2. **Порівняння з `scipy.integrate.quad`.** `quad` — це адаптивна квадратура (Gauss-Kronrod), яка для гладкої функції `x²` дає точність на рівні машинного нуля (`~10⁻¹⁴`), на ~10 порядків точніше за Монте-Карло. **Для одновимірних інтегралів від гладких функцій MC принципово гірший за квадратури.**

3. **Збіжність MC — `O(1/√N)`.** Щоб зменшити похибку в 10 разів, потрібно збільшити `N` у 100 разів. Це накладає жорсткі обмеження на точність: для похибки `10⁻⁶` знадобиться `~10¹²` зразків — це години обчислень.

4. **Метод середнього vs hit-or-miss.** Обидва дали практично однакову точність (~0.001%) на цьому прикладі, але **метод середнього** теоретично ефективніший: він використовує точне значення `f(xᵢ)`, тоді як hit-or-miss зводить його до бінарного `≤/>`. На функціях з широким діапазоном значень різниця між ними помітніша.

5. **Коли Монте-Карло справді виграє.**
   - **Багатовимірні інтеграли:** для `d` вимірів квадратури вимагають `N^d` точок (curse of dimensionality), MC лишається `O(1/√N)` **незалежно від розмірності**. Тому MC незамінний у фінансах (Black-Scholes для опціонів з багатьма базовими активами), фізиці (інтеграли по шляхах Феймана), машинному навчанні (Bayesian inference).
   - **Складна область інтегрування:** якщо область задана нерівностями (наприклад, перетин кількох поверхонь), MC простіше реалізувати, ніж адаптивно розбивати на підобласті.
   - **Інтеграли з розривами/особливостями:** квадратури можуть давати погані оцінки, MC залишається робочим.

6. **Висновок для нашої задачі.** Для одновимірного інтеграла гладкої функції `x²` правильний вибір — `scipy.quad` (швидко й точно). Монте-Карло тут — **навчальний** інструмент, який показує сам метод, але непрактичний як виробниче рішення. У реальній роботі MC застосовується там, де аналітичні/квадратурні методи неможливі (багато вимірів, складна геометрія, стохастичні моделі).
