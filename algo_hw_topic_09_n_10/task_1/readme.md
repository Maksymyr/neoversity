# Завдання 1 — видача решти (greedy vs DP)

Дві реалізації касової задачі: видати решту покупцеві найменшою кількістю монет з набору `[50, 25, 10, 5, 2, 1]`.

## Запуск

```bash
python coins.py        # демо на 113, 999, 1234 + бенчмарк
python test_coins.py   # тести
```

## Алгоритми

### `find_coins_greedy(amount)` — жадібний
Сортує номінали за спаданням і для кожного бере `count = amount // coin`, віднімає `count * coin` від залишку. Складність — **O(k)**, де `k` — кількість номіналів (для нашого набору `k = 6`, тобто **константа**, незалежно від суми).

### `find_min_coins(amount)` — динамічне програмування
Класична DP `min_coins[i] = min(min_coins[i - coin] + 1 for coin in coins)`. Складність — **O(amount × k)** за часом і `O(amount)` за пам'яттю. Backtrack через масив `last_coin` відновлює конкретний набір монет.

## Порівняння часу виконання

| amount   | greedy (μs)  | DP (μs)        | DP / greedy |
|----------|--------------|----------------|-------------|
| 100      | 0.276        | 28.5           | 103×        |
| 1 000    | 0.280        | 310.7          | 1 111×      |
| 10 000   | 0.280        | 3 056.3        | 10 916×     |
| 100 000  | 0.272        | 34 659.3       | **127 579×** |

**Greedy** — фактично константа (~0.28 μs незалежно від суми). **DP** — лінійно зростає з amount (×10 amount → ×10 часу), що повністю відповідає теоретичній `O(amount × k)`.

## Висновки

1. **На канонічному наборі `[50, 25, 10, 5, 2, 1]` greedy завжди дає оптимум** — той самий, що й DP. Це властивість канонічних монетних систем (євро, долар, гривня): для будь-якої суми «брати найбільшу монету, що влізає» дає мінімальну кількість. Тести це підтверджують: на всіх тестових сумах `len(greedy) == len(DP)`.

2. **Greedy на порядки швидший.** На сумі 100 000 копійок DP виконується **~127 000 разів повільніше** за greedy. Причина — `O(amount × k)` vs `O(k)`: для великих сум DP стає неприйнятним (на amount = 1 000 000 уже секунди), greedy — мікросекунди.

3. **Але greedy не універсальний.** На **не-канонічному** наборі, наприклад `[1, 3, 4]`, для суми 6:
   - greedy: `4 + 1 + 1 = 3 монети`;
   - DP: `3 + 3 = 2 монети`.

   Greedy програє, бо локально оптимальний вибір (4) робить неможливим краще глобальне розбиття. Це покрито тестом у `test_coins.py`.

4. **Висновок практичний.**
   - Якщо монетна система **канонічна** (більшість реальних валют — так) → **використовуйте greedy**: оптимум за константний час.
   - Якщо система **довільна** (нестандартні номінали, обмежена кількість монет, валюта зі змінами) → **DP** — єдиний спосіб гарантувати мінімум.
   - **Як перевірити канонічність:** для всіх сум від 1 до `2 × max(coins)` greedy має давати той самий результат, що й DP. Якщо так — система канонічна.

5. **Теоретичні складності:**
   | алгоритм | час            | пам'ять    | оптимальність                          |
   |----------|----------------|------------|----------------------------------------|
   | greedy   | `O(k)`         | `O(k)`     | тільки для канонічних монетних систем  |
   | DP       | `O(amount·k)`  | `O(amount)`| завжди                                 |

   Greedy — це O(1) щодо amount (k — мала константа). DP — псевдо-поліноміальний за amount.
