# Завдання 3 — алгоритм Дейкстри з бінарною купою

Знаходження найкоротших шляхів від однієї вершини до всіх інших у зваженому графі з невід'ємними вагами.

## Запуск

```bash
python dijkstra.py        # демо на графі з 6 вершин
python test_dijkstra.py   # тести
```

## Реалізація

Граф зберігається як вкладений словник: `{вершина: {сусід: вага, ...}}`.

- `dijkstra(graph, source)` — повертає словник найкоротших відстаней від `source` до всіх вершин (`math.inf` для недосяжних).
- `dijkstra_with_paths(graph, source)` — додатково повертає словник попередників для відновлення шляху.
- `reconstruct_path(predecessors, target)` — будує шлях від source до target.

**Алгоритм** (canonical):
1. `dist[v] = ∞` для всіх; `dist[source] = 0`.
2. Min-heap (через `heapq`) з парами `(distance, vertex)`, стартуємо з `(0, source)`.
3. Поки heap не порожній:
   - Витягуємо `(d, u)` з найменшою `d`.
   - **Lazy deletion**: якщо `d > dist[u]` (застаріле значення з купи) — пропускаємо.
   - Для кожного сусіда `v`: якщо `dist[u] + w(u,v) < dist[v]`, оновлюємо й кладемо в купу.

**Складність** з бінарною купою: `O((V + E) log V)`. Для розрідженого графа (E ≈ V) це `O(V log V)` — суттєво краще, ніж `O(V²)` у наївній версії без купи.

**Чому потрібна купа.** Без купи ми б на кожній ітерації лінійно шукали вершину з мінімальною `dist` серед невідвіданих — це `O(V)` за пошук × `V` ітерацій = `O(V²)`. Купа дає `O(log V)` за `extractMin` і `O(log V)` за relaxation, що множиться на `V + E` операцій.

**Обмеження.** Алгоритм вимагає **невід'ємних** ваг. Від'ємні ребра → `ValueError` (для них потрібен Bellman-Ford або Johnson).
