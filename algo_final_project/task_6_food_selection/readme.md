# Завдання 6 — жадібний алгоритм vs динамічне програмування

Задача: вибрати страви з максимальною сумарною калорійністю при заданому бюджеті. Кожна страва має `cost` і `calories`; кожну можна або взяти, або не взяти (0/1 knapsack).

## Запуск

```bash
python food_selection.py        # порівняння на 4 бюджетах
python test_food_selection.py   # тести
```

## Алгоритми

### `greedy_algorithm`
Сортує страви за спаданням відношення `calories/cost` і набирає по черзі ті, що влізають у бюджет. Складність `O(n log n)`. **Не гарантує** оптимальності — пропускає «дорогі, але цінні» страви, якщо «дешеві з високим ratio» вже зайняли місце.

### `dynamic_programming`
Класичний **0/1 knapsack** через 2D-таблицю `dp[i][b]` — максимальна калорійність при використанні перших `i` страв і бюджеті `b`. Рекурентне співвідношення:

```
dp[i][b] = max(
    dp[i-1][b],                              # не беремо i-ту страву
    dp[i-1][b - cost[i]] + cal[i]            # беремо (якщо вмещається)
)
```

Складність `O(n · B)` за часом і пам'яттю, де `B` — бюджет. Гарантує оптимум. Backtracking по таблиці `dp` відновлює конкретний список обраних страв.

## Результати на заданих даних

| Budget | Greedy: cost / cal / items                                    | DP: cost / cal / items                                            | DP виграє |
|--------|---------------------------------------------------------------|-------------------------------------------------------------------|-----------|
| 50     | 50 / **670** / [cola, potato, pepsi]                          | 50 / **670** / [pepsi, cola, potato]                              | —         |
| 75     | 50 / 670 / [cola, potato, pepsi]                              | 70 / **770** / [hot-dog, cola, potato]                            | +100 (15%) |
| 100    | 80 / 870 / [cola, potato, pepsi, hot-dog]                     | 100 / **970** / [pizza, pepsi, cola, potato]                      | +100 (12%) |
| 150    | 120 / 1120 / [cola, potato, pepsi, hot-dog, hamburger]        | 140 / **1220** / [pizza, hamburger, pepsi, cola, potato]          | +100 (9%) |

**Висновок.** Жадібний алгоритм дає прийнятне (а інколи й оптимальне) рішення дуже швидко, але систематично програє DP на бюджетах ≥ 75. Різниця — типово 10–15% калорійності. DP коштує `O(n·B)` часу, що прийнятно для невеликих бюджетів, але масштабується гірше за greedy при великих B.

Якщо потрібен гарантований оптимум — **DP**. Якщо швидкість критична, а 10% похибка прийнятна — **greedy**.
